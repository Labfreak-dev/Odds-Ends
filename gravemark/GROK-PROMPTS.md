## Read this first — it is why the last three packs did not work

Grok makes **one image per prompt**. It cannot produce:

- **Sprite strips.** Every sheet so far came back as the same pose copied eight times. Do not ask for strips. Ask for one pose; the game now reads frame count from the image itself, so a single frame is valid art and installs cleanly.
- **Aligned paper-doll layers.** Three attempts returned item illustrations on white cards instead of gear drawn onto the body. There is no longer any gear to draw: a hero is a whole unit, and each class needs exactly one finished figure (section 1).

### Rules for every prompt below

1. **One image, one subject.** No grids, no sheets, no multiple views, no turnarounds.
2. **Flat magenta background, `#FF00FF`.** Say it explicitly. Nothing in this game's palette is magenta, so the installer keys it out cleanly. Do not ask for transparency — it comes back as a white card, and a white card on a dark backdrop is a bright rectangle.
3. **No text.** No labels, captions, letters, numbers, signature or watermark. Rune glyphs are the sole exception and must be invented marks, not real letters.
4. **Exact pixel size** is given per asset. Square unless stated.
5. **Full subject in frame**, small margin, nothing cropped at the edges.

Paste the style block, then one asset prompt.

```
STYLE: hand-painted 2D game art, painterly with visible brush texture. Cold, damp,
cut stone — a working graveyard that has been working far too long. Weathered granite,

it, no vignette, no border, no frame, no card.

NO text, letters, numbers, watermark, signature or logo anywhere in the image.
```

## 1b. Animation — read this, it is why eight packs produced none

**102 sheets are currently a single still image.** They load and play and nothing moves. Every previous delivery asked for "an 8-frame sheet" and returned the same pose copied eight times.

**Do not ask for a sheet. Ask for individual poses, numbered.**

The game reads frame count from the image's own width, so a **3-frame** animation is completely valid art. Three real key poses beat eight identical ones. Deliver separate files:

```
  actor/hero-attack-sword-1.png     wind-up
  actor/hero-attack-sword-2.png     the strike landing
  actor/hero-attack-sword-3.png     recovery
```

and I stitch them into the strip the game wants:

```bash
python3 tools/make-sheet.py <your-folder>
```

**The one rule that makes or breaks this:** every frame of an action must be the *same character in the same place* — same size, same footing, same distance from the camera. Only the pose changes. Upload frame 1 as a reference image when prompting frame 2, and say *"identical character, identical framing and scale, only the pose changes"*. Without that they come back as three different drawings and the animation strobes.

Priority order: the hero's attack swings first (they fire on every hit, so they are the most visible motion in the game), then monster attack and death, then walk cycles.

## Delivery

- One PNG per key, named exactly as the key: `mon/shambler-idle` → `mon/shambler-idle.png`.
- Any size is accepted if the aspect is right — the installer will not resize, so hitting the listed pixel size exactly avoids a rejection.
- Magenta backgrounds are keyed out automatically on install; a stray magenta fringe is fine.
- Zip the `art/` tree and send it. Partial deliveries are fine and land the same day.

**If only one thing gets made next, make `actor/look-reaver`.** It proves the class-look approach end to end in a single image, and I can tell you within a minute of receiving it whether it works.
